{% extends "base.html" %} {% block title %}Confirm your order — Candy shop{% endblock %} {% block main_class %}narrow{% endblock %} {% block content %} {% comment %} UC-08: the exact order, confirmed three times by three different actions -- a checkbox, typing the total, and the Place my order button -- each worded differently, not three presses of one button. With Alpine, each control unlocks only when the one before it is done. That is not relied on: shop.forms.ConfirmOrderForm checks all three on the server, and without JavaScript all three are simply there to use. Enter in the total field must not place the order, or typing the total and placing it would be one action. The form's first submit button -- its default button, which Enter would press -- is a hidden, disabled one, and HTML submits nothing through a disabled default button. No script involved, so it holds before Alpine loads and without JavaScript too. The two inputs come from the form rather than being written out here, so a refused control is marked aria-invalid and points at its own error message (findings.md F2). The form sets use_required_attribute = False, so rendering them this way does not also hand the browser a `required` it never had: the refusals stay the server's, worded, and reachable. The Place my order button is not a form field; it points at its message only when there is one. `shown` posts back a fingerprint of the order this page showed; the view refuses a confirmation of any other. `token` names this showing of the page, so submitting it twice places one order (Order.objects.place). `matches()` repeats the server's reading of a typed total (a leading $ and a decimal comma allowed) only to decide when to unlock the button. {% endcomment %}
